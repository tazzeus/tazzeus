Sai que horas?

Sai que horas? é um agregador de horários de transporte intermunicipal de Sergipe: várias empresas
de transporte expõem seus horários num só portal público, e cada empresa administra os próprios
dados sem depender de um desenvolvedor a cada mudança de grade. Piloto: Coopertalse (dado já
verificado, carregado a partir de um snapshot herdado). Português do Brasil (produto e código).

🧭 O que o sistema NÃO faz (ainda): não existe deploy público — o projeto roda 100% local
(Postgres em Docker + next dev) até a hospedagem definitiva ser decidida (ver
Estado atual e pendências). O login Google também não está
funcional de ponta a ponta: falta só a credencial real do
Google Cloud Console, que só o dono do
produto pode criar.

📖 A fonte de verdade do projeto é a spec, não este README. Antes de mudar qualquer coisa,
leia .specify/memory/constitution.md e
specs/001-agregador-multiempresa/ (spec.md, plan.md,
data-model.md, tasks.md). O método é Spec-Driven: spec → plano → tarefas → código, sem
improviso em cima de ambiguidade.

🚀 Arquitetura & Tecnologias

O projeto é um monorepo pnpm, com a regra de negócio de busca vivendo um único lugar
(packages/engine, TypeScript puro) e compartilhada por todas as plataformas — nenhuma delas
reimplementa a busca por conta própria:

  1. 🖥️ apps/web — Next.js 16 (App Router, TypeScript estrito). Serve a página pública de
    busca e o painel administrativo (multiempresa). Com servidor de verdade (não é estático):
    permissão por papel/empresa e edição de dado sem deploy exigem isso.
  2. 📱 apps/mobile — Expo/React Native. Mesma busca pública do web (packages/engine +
    GET /api/snapshot), sem login — os painéis administrativos ficam só na web por enquanto.
  3. 🗄️ Postgres + pgvector (via Prisma) — fonte de verdade dos dados: empresas, usuários,
    localidades, rotas, horários e os embeddings de localidade.
  4. 🐍 services/ingest (Python 3.14, uv) — só ingestão em lote, nunca serve API nem
    reimplementa busca: carga inicial do snapshot herdado da Coopertalse, geração dos embeddings
    de localidade e coordenadas dos municípios (IBGE).
  5. 🔐 Auth.js v5 — login só Google, sem conta com senha própria, para a área privada
    (super admin / admin de empresa / gerente de empresa).

🏢 Arquitetura Multiempresa (Papéis)

Uma empresa de transporte nasce Pendente no agregador e vira Ativa sozinha assim que a
primeira rota/horário é salvo — sem clique extra de ninguém. Três papéis, cada um só enxergando o
que lhe cabe (verificado como caso de segurança, não só de produto):

Papel Escopo Pode
Super administrador Todas as empresas Cadastrar empresa, mudar status (Ativa/Inativa), ver os indicadores do site
Admin da empresa Uma empresa Dados cadastrais (inclusive Instagram), convidar/bloquear/inativar/excluir gerente, rotas e horários
Gerente da empresa Uma empresa CRUD de rotas e horários (carro, via, postagem) — nunca dado cadastral nem usuários

Toda escrita passa por uma camada única (apps/web/src/server/) que valida papel e empresa
antes de tocar o banco — nunca confia só no que a interface esconde. Nenhum código específico de
uma empresa vive espalhado pelo projeto: é tudo dado, não bifurcação.

📦 Instalação & Ambiente

Requer Node 20+, pnpm, Docker (Postgres local) e Python 3.14 + uv (só pra ingestão). Tudo que a
carga inicial precisa (snapshot da Coopertalse, schema, migrations, script de usuários de teste)
já vem versionado no repositório — não há passo manual fora do git nem arquivo pra copiar de outra
máquina.

git clone https://github.com/tazzeus/sai_que_horas.git
cd sai_que_horas
git checkout dev   # branch de trabalho — é a branch padrão do repositório

pnpm install       # instala tudo e já gera o Prisma Client (postinstall)

# .env de cada pacote — se a porta 5432 já estiver em uso nesta máquina, troque nos três (e em
# db/.env use DB_PORT=<porta> em vez de mexer no docker-compose.yml).
cp apps/web/.env.example apps/web/.env.local
cp db/.env.example db/.env
cp services/ingest/.env.example services/ingest/.env
# gera um AUTH_SECRET novo e cola em apps/web/.env.local
npx auth secret

cd db && docker compose up -d && cd ..              # Postgres local com pgvector
pnpm --filter @via-certa/db migrate:dev             # aplica o schema

cd services/ingest && uv sync
uv run ingest carregar-inicial      # carrega os 2.762 horários reais da Coopertalse
uv run ingest gerar-embeddings      # gera os embeddings de localidade (autocompletar)
uv run ingest carregar-coordenadas  # coordenadas dos municípios (IBGE) — botão de localização
cd ..

pnpm --filter @via-certa/web dev    # sobe em http://localhost:3000

🧪 Testar o painel sem Google: em apps/web/.env.local ponha AUTH_DEV_LOGIN="true" e rode
pnpm --filter @via-certa/db seed:dev (cria/atualiza três usuários fixos — super@dev.local,
admin@dev.local, gerente@dev.local, um de cada papel, o admin/gerente já vinculados à
Coopertalse). A tela /entrar ganha um campo de e-mail que aceita qualquer um dos três (só em
desenvolvimento local — em produção esse caminho não existe).

🚨 Login Google não funciona sem credencial real. Crie um "Web application" em
Google Cloud Console (redirect URI
http://localhost:3000/api/auth/callback/google) e cole em apps/web/.env.local
(AUTH_GOOGLE_ID/AUTH_GOOGLE_SECRET) — ver apps/web/.env.example. Sem isso, a busca pública
funciona normalmente; só a área /painel fica inacessível.

⚙️ Comandos do Dia a Dia

pnpm check                                  # lint + tipos + testes de todo o monorepo (espelha o CI)
pnpm --filter @via-certa/web test           # só os testes do web (Vitest, contra o Postgres local)
pnpm --filter @via-certa/db studio          # Prisma Studio — inspecionar o banco visualmente
pnpm --filter @via-certa/db seed:dev        # (re)cria os 3 usuários de teste do login de dev

cd services/ingest
uv run pytest                               # testes Python (carga inicial + embeddings)
uv run ingest gerar-embeddings              # reexecutar quando uma localidade nova entrar
uv run ingest carregar-coordenadas          # reexecutar quando uma cidade nova entrar

cd apps/mobile
npx expo start --web                        # app mobile no navegador (mesma busca do web)

💾 Levar o banco local de uma máquina pra outra (cadastro real de empresa/usuário, Instagram,
rotas/horários editados pelo painel — nada disso é gerado pela carga inicial nem entra no git):
pnpm --filter @via-certa/db backup grava db/backups/viacerta-<data>.dump (fora do git — é
dado real, não código); copie esse arquivo pra máquina nova e rode
pnpm --filter @via-certa/db restore -- <arquivo> (ou sem argumento, pra pegar o mais recente
em db/backups/) depois de já ter feito docker compose up/migrate:dev lá. Substitui o
conteúdo atual do banco de destino. Não é pré-requisito pro sistema funcionar — a carga inicial +
seed:dev já deixam tudo utilizável; isso aqui é só pra não perder dado digitado à mão.

🧮 Motor de Busca Determinístico & Vetor Assistivo

A busca nunca inventa nem estima horário — só filtra e ordena o que está no banco, com o rastro
até a fonte sempre visível (PDF da empresa, post transcrito, ou "informado pela empresa no
portal"). Três garantias centrais em packages/engine:

  • agoraEmMaceio — único ponto que toca fuso horário (America/Maceio), independente do
    fuso do aparelho de quem está buscando.
  • Dia efetivo e feriado — em feriado, a grade vira a de domingo automaticamente, sempre com
    aviso; a empresa pode sobrescrever isso quando informa a regra própria.
  • sugerirLocalidades — autocompletar por trigrama (tolera erro de digitação, acento e
    apelido) sem depender de banco vetorial nenhum — funciona sozinho.

O banco vetorial (pgvector + paraphrase-multilingual-MiniLM-L12-v2 rodando local via
fastembed/ONNX, sem chave de API) só reforça esse autocompletar quando a busca por trigrama
não encontrou nada — nunca decide sozinho o que aparece, e a pontuação do reforço semântico nunca
ultrapassa a de um match exato determinístico.

🛡️ Princípios de Confiabilidade (Constituição)

Regras que não se negociam sem um ADR registrado em docs/adr/ (ver
.specify/memory/constitution.md pro texto completo):

  • A fonte é sagrada — nenhum horário aparece sem rastro até a origem; nada é estimado.
  • Isolamento entre empresas desde o dia 1 — vazamento de dado entre empresas é bug de
    segurança, testado como tal, não só de produto.
  • Papéis de menor privilégio — toda rota privada verifica papel e empresa, nunca só um
    dos dois.
  • Vetor é assistivo, nunca autoridade — quem decide o resultado da busca é sempre o motor
    determinístico.
  • Spec-driven, sem TDD obrigatório — spec → plano → tarefas → código; ambiguidade vira
    pergunta ao dono do produto, nunca suposição no código. Teste automatizado é bem-vindo onde
    agrega valor, não é pré-requisito de tarefa.
